1 · GITHUB_TOKEN permissions
0/6

The token generated on each run has, by default, a scope that depends on the repo's settings - often too broad. Reducing these rights is the first barrier: a compromised step can only do as much damage as the token allows.

Rule of thumb: security-events: write is only needed to publish SARIF; packages: write only to publish a package; otherwise contents: read is usually enough.

2 · Third-party actions (uses:)
0/8

Every uses: runs code written by a third party, with your secrets and your token. A popular compromised action contaminates thousands of pipelines (cf. the tj-actions/changed-files incident, 2025).

# .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: "github-actions"
    directory: "/"
    schedule:
      interval: "weekly"

4 · Command injection
0/2

The most common workflow flaw. Interpolating a third-party-controllable value with ${{ }} inside a run: block allows arbitrary code execution on the runner.

# ❌ Vulnerable: the title is injected into the shell
- run: echo "Issue: ${{ github.event.issue.title }}"

# ✅ Safe: the title stays a plain string
- run: echo "Issue: $ISSUE_TITLE"
  env:
    ISSUE_TITLE: ${{ github.event.issue.title }}
